    Unidad 4. Programación Orientada a Objetos en Java

    Introducción

    Los conceptos de Programación Orientada a Objetos (POO) que ya conoces de Python (clases, objetos, atributos y métodos) son exactamente los mismos en Java. Lo que cambia es la sintaxis y el nivel de rigor que impone el lenguaje.

    En esta unidad aprenderás a aplicar los conocimientos que ya tienes de Python, comparando continuamente ambos lenguajes para facilitar la transición.

    Las principales diferencias son:

    • Tipado estático: hay que declarar el tipo de cada variable, atributo y parámetro.
    • Control de acceso real mediante modificadores como private.
    • Getters y setters para acceder a atributos privados.
    • Constructores con el nombre de la clase en lugar de __init__().
    • Métodos especiales como toString(), equals() y hashCode(), equivalentes a __str__(), __eq__() y __hash__().

    4.1. Cómo se organiza el código

    En Java existe una organización más estricta del código:

    • Una clase public debe estar en un archivo con el mismo nombre.
    • La clase Alumno debe almacenarse en Alumno.java.
    • El programa comienza a ejecutarse en el método main().

    Los conceptos son idénticos:

    • Una clase es una plantilla.
    • Un objeto es una instancia concreta.
    • Los atributos almacenan información.
    • Los métodos definen comportamientos.

    Java exige indicar explícitamente los tipos y utiliza la palabra clave new para crear objetos.

    Simplificación temporal

    En los primeros ejemplos los atributos no llevan private. Más adelante veremos la forma correcta de declararlos.

    4.10. Relaciones entre objetos

    Hasta ahora hemos creado objetos aislados. Sin embargo, en los programas reales los objetos interactúan entre sí.

    Por ejemplo:

    • Un vehículo tiene un motor.
    • Un alumno pertenece a un grupo.
    • Un pedido contiene productos.

    La solución orientada a objetos consiste en relacionar clases mediante referencias.

    4.15. Direccionalidad: ¿Quién conoce a quién?

    Relación unidireccional

    Solo una clase conoce a la otra.

    1
    Vehiculo ---> Motor

    1
    coche.getMotor();

    Es la opción más habitual.

    Relación bidireccional

    Ambas clases almacenan referencias mutuas.

    1
    Vehiculo <----> Motor

    1
2
3
    vehiculo.getMotor();

motor.getVehiculo();

    Solo debe utilizarse cuando sea realmente necesario navegar en ambos sentidos.

    import java.util.Objects;

public class Alumno {

    private String nombre;
    private int edad;

    public Alumno(String nombre, int edad) {
        this.nombre = nombre;
        setEdad(edad);
    }

    public String getNombre() {
        return nombre;
    }

    public void setNombre(String nombre) {
        this.nombre = nombre;
    }

    public int getEdad() {
        return edad;
    }

    public void setEdad(int edad) {

        if (edad < 0) {
            throw new IllegalArgumentException(
                    "La edad no puede ser negativa: " + edad);
        }

        this.edad = edad;
    }

    @Override
    public String toString() {
        return String.format(
                "%s (%d años)",
                nombre,
                edad);
    }

    @Override
    public boolean equals(Object obj) {

        if (this == obj) {
            return true;
        }

        if (obj == null || getClass() != obj.getClass()) {
            return false;
        }

        Alumno otro = (Alumno) obj;

        return Objects.equals(nombre, otro.nombre)
                && edad == otro.edad;
    }

    @Override
    public int hashCode() {
        return Objects.hash(nombre, edad);
    }

}

    Resumen

    Al finalizar esta unidad debes ser capaz de:

    • Crear clases y objetos.
    • Utilizar atributos y métodos.
    • Implementar constructores.
    • Aplicar encapsulación mediante private.
    • Crear getters y setters.
    • Validar datos.
    • Utilizar this.
    • Sobrescribir toString().
    • Diferenciar == y equals().
    • Implementar correctamente hashCode().
    • Comprender el uso de null.
    • Relacionar objetos mediante referencias.
    • Diseñar relaciones 1:1 y 1:N.
    • Implementar relaciones unidireccionales y bidireccionales sencillas.

    Errores típicos de quien viene de Python

    Error Corrección
    Comparar objetos con == Utilizar equals()
    Comparar String con == Utilizar equals()
    Llamar a new Alumno() sin constructor vacío Crear constructor sin parámetros
    Sobrescribir equals() sin hashCode() Sobrescribir ambos
    Saltarse la validación en el constructor Utilizar setters
    Utilizar una referencia null Inicializar o comprobar antes
    Escribir código fuera de métodos Colocarlo dentro de main()
    Colocar una clase public en otro archivo Nombre de clase y archivo deben coincidir
    Invocar métodos sobre una referencia null Comprobar con if antes de acceder
    Crear relaciones bidireccionales innecesarias Preferir relaciones unidireccionales
    Guardar muchos objetos en atributos duplicados Utilizar clases relacionadas
